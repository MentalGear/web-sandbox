# Capabilities removed or restricted because of a finding

Repo state read: `main` at `be0a34a` (docs, ADR-004 to ADR-007, `docs/archive/backlog/BACKLOG-done.md`, `docs/archive/adr/*-history.md`, the review reports).

ID forms follow the board registry: `AR:` adversarial review, `FR:` focused, `BR:` broad, `VR:` verification, `R1:` to `R5:` the numbered rounds, `BD1:`, `BD2:` and `BD3:` board passes (`P3:` in the last table is `BD3:`), `S<n>` backlog items. "Opt-in" is whether the embedder can get the old behaviour back with a config option, in a supported mode.

Mode names: strict = the default (worker plus inert view); cooperative = the old `iframe` mode (renamed S48); worker = worker in the frame.

Rows are grouped by scope in the order: sandbox flags, policy surface, host page (embedder), guest network, guest runtime (cooperative and worker), guest runtime (strict worker), strict view, budgets and limits.

## Caveats

- Rows 7, 8, 9 (strict part), 10, 34 (Blob type limit), 40 (default flip) were driven by the owner's 2026-10-23 ruling that the API behaves the same on every engine, applied after board pass 2; they have no BD ID of their own. I cited the nearest finding and the commit.
- Rows 24 to 26 and 28 (S9, S10, S11, S13, S15, S17, S18) come from issue #6 and research notes, before the review rounds; included because they are findings that removed guest capabilities.
- "Before" for row 4 and 19 describe the library as of 2026-10-13/14 (ADR-007, S48). Nothing was published, so no external embedder was affected (ADR-007 says "with nothing published, a warning and fail-closed is the honest migration").
- A restriction that fails closed with a warning (rows 4, 8, 9, 10) can be invisible to a guest UI; the embedder sees a warning, the guest just cannot reach the origin.
- Browser-owned limits that the library only documents (modifier-click tabs V3, focus and clipboard PD5, WebKit preconnect PD3 residual, session history H1) are not capabilities the library removed, so they are not listed.
